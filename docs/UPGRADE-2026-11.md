## 3. Риски — по убыванию

### R1. sing-box 1.13 и Reality (блокирующий)

В официальном фиде 25.12.6 лежит `sing-box 1.13.21`. Именно эта пара
(sing-box 1.13.21 ↔ Xray 26.x из 3x-ui) на стенде 2026-09-25 давала
`reality verification failed` при верных ключах, shortId, SNI и времени — это
открытый P1 в `TECHNICAL_README.md`. Боевой сейчас работает на `1.12.22`.

То есть переход на 25.12.6 **может уронить весь обход**, и E2E этого не поймает
(тест ходит на `google.com`, который не в списках). Проверять надо на стенде
доменом из списков.

Запасные ходы: поставить `sing-box 1.12.22` вручную поверх, либо идти на 24.10.8,
где в фиде ровно та же `1.12.22`, что работает сейчас.

### R2. Корп-VPN сейчас сломан сам по себе

По `delohom-stacks/docs/corp-vpn-router/UPGRADE-OPENCONNECT.md` (правлен сегодня):
ASA обновилась 2026-11-06, `openconnect 9.12` неверно считает STRAP channel binding
под TLS 1.3, туннель отбивается `401`. Исправлено в openconnect 9.20+, а в фидах
и 24.10.3, и 25.12.6 лежит `9.12`. Нужна своя сборка из SDK — **и SDK привязан к релизу**.
Значит порядок такой: сначала выбрать целевой релиз, потом собирать openconnect под него,
а не наоборот. План сборки в доке написан под SDK 24.10.3 — под 25.12.6 его придётся
переписать. Плюс `restore.sh` там на `opkg` — для 25.12.x нужен apk-вариант.

### R3. `nft-qos` выпилен из 25.12.x

Ни `nft-qos`, ни `luci-app-nft-qos` в фидах 25.12.6 нет. Текущий лимит на `10.10.10.4`
придётся перенести на QoS самого Warren (`lib/qos.sh`, чистый nft) или на SQM.
На 24.10.8 пакет ещё есть.

### R4. Миграция WG → AWG ломает всех 8 клиентов

Новые ключи, новые конфиги, раздать всем. И тут важное: **M19 (обфускация по умолчанию)
ещё `planned`**. Сегодняшние дефолты AWG в Warren (`S1=S2=0`, `H1..H4=1..4`, порт 51820)
дают рукопожатие, побайтово совпадающее с обычным WireGuard, — то есть переезд
«как есть» не даёт почти ничего против DPI. Разумно закрыть M19 **до** раздачи конфигов,
чтобы не выдавать людям конфиги дважды.

### R5. Ядро 6.6 → 6.12

Меняются `r8169` / `kmod-phy-realtek`, `packet_steering`. На R5S обычно без проблем,
но это ровно тот класс сюрпризов, который ловится только на железе.

### R6. Внешние kmod после sysupgrade

Все не-фидовые kmod (AWG) переустанавливаются под точный тег релиза. Это умеет Warren,
но важно не забыть при ручных шагах.

## 4. Нужен ли тестовый роутер — да

И именно твоим сценарием: подготовить второй R5S 1-в-1 и просто поменять железку.
Почему это сильно лучше апгрейда на месте:

- R1 (Reality) и R5 (ядро) проверяются только на железе, а на боевом цена ошибки —
  интернет всему дому и упавший корп-доступ;
- корп-VPN требует своей сборки openconnect — это пара часов работы, которую нельзя
  делать на живом роутере;
- откат при hot-swap — минута (поменять железку обратно), а не «восстанавливаем из бэкапа ночью»;
- заодно закрываем M19 и перевыпускаем клиентов один раз, спокойно.

Стенд уже есть: `192.168.1.1` через USB-сетевуху (`ssh -b 192.168.1.159`, инструменты
Warren это делают сами). Стенд держим на `192.168.1.1` до самой замены, чтобы не
конфликтовать с боевой `192.168.0.1`.

Что мне от тебя нужно для стенда: он должен быть включён и доступен, и желательно
с тем же eMMC-объёмом. Под замену железки понадобится ещё одно: **клонировать MAC
eth0** (`<MAC-eth0>`) на новый роутер, если провайдер привязывает выдачу к MAC.

**Это снимает главный риск замены железки.** Приватный ключ `wg0` и ключи всех
клиентов сохранены, значит новый роутер поднимается с **теми же** ключами WireGuard
и ни один клиент при hot-swap ничего не замечает. Переезд на AmneziaWG перестаёт
быть частью замены и делается отдельным спокойным шагом — см. правку Фазы 5.

### Фаза 1. Стенд: голый 25.12.6 + проверка R1

1. Прошить стенд образом 25.12.6 ext4-sysupgrade, expand-root.
2. Поставить Podkop + восстановить списки из снапшота Фазы 0.
3. **Проверить Reality на домене из списков** (`instagram.com`: fake-IP `198.18.0.0/15`
   + живой HTTPS + ноль ошибок sing-box в `logread`), на всех трёх endpoint'ах.
4. Развилка: работает → дальше; не работает → ставим `sing-box 1.12.22` вручную и
   проверяем снова; не помогло → переигрываем план на 24.10.8.

### Фаза 2. Стенд: AWG с нормальной обфускацией

1. Закрыть M19: генерация `H1..H4`/`S1`/`S2`/`Jc`/`Jmin`/`Jmax`/порт по правилам,
   единый источник параметров из UCI для shell / LuCI / TG-бота.
2. Поднять AWG-сервер, выпустить 8 клиентов с именами как у WG-пиров.
3. Проверить handshake и трафик с реального телефона из мобильной сети.
4. Проверить, что AWG-интерфейс попал в `source_network_interfaces` Podkop
   (у WG это `wg0`, у AWG будет `awg0`).

### Фаза 3. Стенд: корп-VPN

1. Собрать `openconnect 9.21` под целевой релиз из SDK (Docker `openwrt/sdk`).
2. Портировать `restore.sh` на apk, развернуть `files/`, донести секреты.
3. Поднять туннель — одна попытка за раз, второй фактор одноразовый, серия отказов
   блокирует учётку AD.
4. Проверить сосуществование с Podkop по `PODKOP-COEXISTENCE.md` и ловушки
   корп-DNS (wildcard в зоне делает любой `nslookup` «успешным» — проверять
   не резолв, а реальный доступ).

### Фаза 4. Остальной паритет

QoS-лимит на место `nft-qos`, DNAT на OMV, DHCP-привязки, TG-бот, watchdog,
Remote Admin, Warren LuCI. Прогнать `tools/test-e2e.sh` на стенде целиком.

### Фаза 5. Замена железки

1. LAN стенда перевести на `192.168.0.1`, клонировать MAC eth0.
2. Поднять на стенде `wg0` со **старыми** ключами из снапшота — все 8 клиентов
   продолжают работать без новых конфигов. AWG на стенде при этом уже настроен
   и живёт параллельно на своём порту.
3. Поменять железку. Боевой старый R5S не трогать неделю — это и есть откат.
4. Новые AWG-конфиги раздавать после замены, по одному клиенту, в своём темпе:
   WG продолжает работать, пока все не переедут. Потом `wg0` выключаем.
5. После недели спокойной работы — старый R5S становится новым стендом.

### Фаза 6. Корп-VPN по плану из анализа

Чистка и сборка — уже на новом роутере, по `delohom-stacks/docs/corp-vpn-router/`.

(`LAST_REASON=sing-box-not-running`) — Podkop при старте сначала качает списки, sing-box
стартует позже, а у watchdog нет grace-периода на загрузку. Через ~минуту `healthy`,
трафик не страдает дольше этой минуты. Стоит поправить до замены (см. TODO).
